# Real relock verification — 2026-10-30

**Result: confirmed for one achievement in one game.**

This post-build check used the delivered 0.8.0-preview Windows worker. The user
requested real relock verification. The selected achievement had previously
been deliberately unlocked during the user's earlier application test; its
reference snapshot recorded the original state as locked.

| Check | Observation |
| --- | --- |
| Game | I Have No Mouth, and I Must Scream |
| Steam App ID | 245390 |
| Achievement API name | `Theyellowhysterical` |
| State before this check | Unlocked |
| Requested operation | Relock this one achievement |
| Steam save acknowledgement | Successful |
| Verified state in a new worker process | Locked |
| Unlock timestamp after relock | 0 |
| Other achievement states and timestamps | All 12 unchanged |
| Native achievement count before / after | 13 / 13 |
| Final state left on the account | Locked, matching the original pre-test state |
| Check completed | 2026-10-30 21:09:02 UTC |

The worker checked the account and current state again, saved a reference
snapshot before mutation, submitted one change, waited for Steam's successful
save callback and read the states again. That worker exited. A separate worker
then reopened the game achievement connection and independently read the locked
state. No game executable was launched and no automatic retry was performed.

The normal local activity history and account-scoped compatibility record were
updated. The app can now show **Relock observed: Yes** for this game/account.
Private evidence and snapshots remain in local folders; account identifiers and
the full achievement list are excluded from this report and public packaging.

An optional Steam Community query did not expose an explicit matching locked
flag. Independent website confirmation is therefore **unconfirmed**. The evidence
for this result is Steam's native acknowledgement and the fresh worker read.

This is evidence for this particular operation. It does not establish universal
game compatibility, trophy awarding/removal, future Steam-client compatibility
or behavior after a game re-awards an achievement. The achievement was not
unlocked again, and its former unlock timestamp was not restored.

No application code change or binary rebuild was needed for this verification.
The original 0.8.0 release archives remain unchanged; this report records the
subsequent live validation.
